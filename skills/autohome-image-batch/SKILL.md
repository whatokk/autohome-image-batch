# 汽车之家作图 · 批量出图流水线

## 何时用
用户给出车辆参考图 + 视角/场景清单（常见 10 张），要求产出"真实车主随手拍"风格的独立图片，用于口碑/内容投放。

## 目录约定（项目根 = 含 `batch.mjs` 的目录）
| 文件 | 作用 |
|---|---|
| `batch.mjs` | 主脚本，Node 零依赖。读提示词文件 → 调 API → 存 PNG |
| `prompts-*.txt` | 每行 `参考图路径<TAB>提示词`，多参考图用 `\|` 分隔；`#` 开头为注释 |
| `config-*.json` | `baseUrl` / `apiKey` / `model` / `size` / `quality` / `retries` / `concurrency` / `outputDir` |
| `ref/<车型>/` | 规格化后的参考图（长边 1536 / JPEG q88，约 300–600KB） |
| `output-*/` | 成品 PNG（`NNN_*.png`）+ `manifest.txt` + `failed.txt` |
| `deliver.py` | 交付脚本：`--src <输出目录> --out <交付目录> --prefix <车型前缀>`，按序号套场景名 + 生成 `_总览.jpg` + 打 zip |
| `run-*.bat` | 一键启动，`chcp 65001` + `cd /d "%~dp0"` + `pause` |
| `使用指南.md` | 面向人的操作手册（5 节，精简版）：环境 / 目录速查 / 标准流程 / 断点续传坑 / 排错速查。需要复述流程给用户时可直接引用，不必从头讲 |

## 通用版（`通用版/`，优先用这个）
已经把上面的专用流程抽象成通用工具 + 本地可视化界面，任意车型复用，**不需要 Python**。

- 入口：双击 `通用版/启动.bat` → 浏览器 `127.0.0.1:5178`（自动找空闲端口）。界面六分区：参考图 / 提示词 / 成品 / 运行 / 交付 / 设置。
- 组成：`core.mjs`（引擎）/ `store.mjs`（批次存储）/ `deliver.mjs`（交付 + 手写 ZIP）/ `server.mjs`（零依赖本地服务 + SSE）/ `cli.mjs`（命令行）/ `public/index.html`（单文件界面）。
- 数据：`通用版/data/<批次名>/` 自包含；新批次继承 `通用版/settings.json` 的接口与 Key。
- 设计取舍：参考图规格化与总览图拼版都交给**浏览器 Canvas**（所以 Node 侧零图像依赖）；ZIP 用 **STORE 模式手写**并带 UTF-8 文件名标志（中文不乱码，不依赖压缩库）。
- 参考图路径相对批次目录，标准写法 `ref/文件名`；写裸文件名也会自动到 `ref/` 下找。
- 回归自测：`.workbuddy/tmp/` 下有 `mock-server.mjs`（假端点，`--strict` 验降级链）、`test-e2e.mjs`（24 项断言全链路，零 API 成本）。**改完 core/store/server 后直接重跑。**
- 尚未覆盖：mask 改图只保留 `mask=` 参数通道，无界面与本地合成；「只换窗外」仍走 `make_mask.py` + `composite_scenes.py`。

## 标准流程
1. **读参考图、识别车型**——先用 PIL 生成缩略图再读（原图 8–12MB 直读易爆上下文），必要时放大关键标识区（后翼子板车型字标、尾部、格栅、尾标、号牌）。
2. **规格化参考图**——`thumbnail((1536,1536))` + `quality=88, optimize=True`，输出到 `ref/<车型>/`。**务必做**，否则 base64 后请求体过大必失败。按角度命名（`front / front34 / rear / rear34 / side / close`）。
3. **写提示词文件**——每条挂 2 张角度匹配的 ref。六段式结构：
   车辆锁定（列明全部识别特征 + 禁止改型/拉长/压扁 + 车身颜色）→ 清除活动道具与后加贴纸、保留原厂标识与号牌 → 移除原参考图背景 → 新场景 → 视角与拍法 → 光线 → 禁止项（拼图/九宫格/多图合成/多车同框/车展展厅/海报感/过度精修/人物/水印）→ 「只输出 1 张独立图片」。
   参考图只有左侧素材时，右视角必须写明「为左侧视角的水平镜像，轮眉/踏板/把手/腰线/轮毂辐条须与参考图对应」。
4. **校验**（每次写完必做）：任务数 = 期望条数；TAB 分隔符正常（**必须真实 TAB，不能是空格或全角**）；所有 ref 路径存在。
5. **跑**：`node batch.mjs --config config-x.json --prompts prompts-x.txt`。放后台跑并设较长 timeout。**断点续传**：已存在的 `NNN_*.png` 自动跳过，失败后原样重跑即可补缺口。
   - **⚠️ 复用输出目录前必查**：断点续传只按文件名前缀 `^\d{3,}_` 判「已完成」。换车型或换参考图后若沿用同一 `output-*`，旧成品会让新批次**被整体跳过、一张都不出**。跑前先把旧成品移出或归档到 `_archive/`。
   - 多批同时跑（每批一个进程）：总并发 = 各批 `concurrency` 之和，超过 3–4 路易触发 `429 上游负载已饱和`。接受重试，或把各批 `concurrency` 降到 1–2。
6. **质检**：拼版总览（PIL 网格）+ 放大关键局部（号牌、前脸、尾部、中控屏）核对；确认视角场景不重复、车身特征一致、号牌正确。
7. **交付**：一步跑 `python deliver.py --src output-x --out "车型_车主随手拍_交付" --prefix V27`（自动重命名 + 总览 + zip）。多批产出就打多个交付目录，互不混淆。中文名必须走 Python `zipfile`，不能用 PowerShell `Compress-Archive`（编码风险）。

## 中转站 API 排错（api.apilio.ai + gpt-image-1）
- **多通道负载均衡**：`/images/generations` 是否接受 `image`、`response_format` **随命中通道而变**。同一提示词一条成功一条持续 400 属正常现象，**不要靠改提示词/换参考图顺序碰运气**。
- `batch.mjs` 已内置三级降级：`gen+image+response_format` → `gen+image` → `/images/edits`（multipart，最终兜底，实测必过）。仅参数类错误才降级，网络/超时/5xx 交外层重试。
- `Your request was rejected by the safety system` → 内容安全拦截，**重试即过**，不必改提示词。
- `fetch failed` / `500` / `503` → 网络抖动，重试即过。
- `429 当前分组上游负载已饱和，请稍后再试` → 并发过高被限流，重试即过；持续出现就降总并发。
- `500 没有按照预期生成图片，请重新调整提示词后重试` → **提示词不必改**，通道侧生成失败，重试即过。
- **降级链在持续退化**：实测该站对 `generations` 的 `image` 参数支持越来越差，一整批里多数请求需降级、末尾几条只能走 `edits` 兜底。这是常态，不必逐条排查。
- 通道差异会导致成品尺寸不齐（`1024x1536` 与 `1086x1448` 混出）；宽高比 2:3 与 3:4 无法无损统一，需对一组做约 11% 中心裁剪，默认接受不统一。
- `mask` 参数**不生效**（中转站接受但忽略，会整图重绘）。需要"只改局部"必须本地合成：生成场景图后按多边形遮罩贴回原图，并在合成后逐像素校验遮罩外零改动。

## 生产质检清单（易错项）
- 车身识别特征逐项对照参考图，特别是：尾部（外挂备胎 / 储物箱）、车顶（行李架样式）、灯组段数、把手形式、轮毂辐条样式。
- 号牌必须是参考图上的真实绿牌号码，字迹自然。
- **清除车主后加贴纸与活动道具**（卡通拉花、宣传横幅、机盖上的杂物、风挡角标），保留原厂标识与车型字标。
- 极易混的同族车型要靠**后翼子板车型字标**和**尾部是否外挂备胎**区分，不要凭整体轮廓判断。
